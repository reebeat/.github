## Problem

Nothing under the old name was published, so the rename costs no consumer. The npm release hold (`.github/release-hold`, compiler) stays until the operator lifts it in a PR of their own.

## Constraints and values

- **History is not rewritten.** Commit shas, line numbers and the path inside a pinned citation (`record:` sources, `blob/<sha>/<path>` URLs) stay as they were; only the repository coordinate changes. Provenance lines (`adapted from <org>/<repo> @ <sha>`) keep the sha.
- **The old name stays where it is the subject**: the keep-list (`rename-prep/keep-list.yaml`), the `formerly` notes, this spec.
- **Frozen specs and design documents are renamed with the code they describe.** This spec is the declaration of that change; the specs it touches get no Revisions entry of their own. Their dated entries, quotations of pinned text and the reasons of decisions about the old name keep the old word (the keep-list says which, and why).
- `bun.lock` is the base lock with the names mapped and nothing else; the repository's own `bun install --frozen-lockfile` accepts it. Generated documents are regenerated by the repository's own command, never edited by the rename.
- `PROVENANCE.md` files gain a note: a file listed as identical to its source may now differ in the brand word alone.
- No external effect in this PR: no organisation, repository, package or domain is created, renamed or registered by it.
